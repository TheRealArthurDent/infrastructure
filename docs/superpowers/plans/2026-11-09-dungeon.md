# dungeon Implementation Plan (#15)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dungeon (Pi 5) is set up by the same `bootstrap.yaml` as raspi, with its own components, KeePass database,
local restic repository on the backup SSD and the `backup_target` role, while raspi and testbed render exactly what
they render today.

**Architecture:** Builds on the component split (#14, merged): every dungeon difference is a host variable in
`inventory/host_vars/dungeon.yaml` with a default that keeps raspi/testbed unchanged. New: KeePass per database,
`backup_target` host role, resticprofile with a local repository, per-host vhosts and Pi-hole instances, a second
Molecule platform.

**Tech Stack:** Ansible (ansible-core via `ansible==14.5.0`), community.docker/crypto, ansible.posix, pytest, Molecule
(Docker driver), bash, PowerShell (via WSL).

**Spec:** `docs/superpowers/specs/2026-11-09-dungeon-components-design.md`

## Global Constraints

- raspi and testbed don't change: golden files in `ansible/tests/unit/golden/{raspi,testbed}` stay byte-identical,
  `test_inventory.py`'s resolved vars for raspi/testbed only gain keys this plan names. Sanctioned changes on raspi:
  `init-restic.sh` is removed; the restic key pair is written from KeePass (same content).
- dungeon: IP `192.168.1.5`, `ansible_port: 1359`, `ansible_user: dragon`.
- dungeon components: `[reverse_proxy, portainer, unbound, outbound, resticprofile, healthmonitor]`.
- Backup SSD: UUID `eeeb6563-1a18-4941-a7bd-72ec86622fa7`, ext4, mount point `/media/backup`, options
  `defaults,noatime,nofail`; marker `/media/backup/.backup-ssd`; dungeon's repository `/media/backup/restic/dungeon`,
  in the container `local:/backup/restic/dungeon`, `/media/backup` bind-mounted as `/backup` with propagation `rslave`.
- `restic` user and group on dungeon: uid/gid `1002`; `/media/backup/restic` owned `restic:restic`, `0700`.
- KeePass: databases named `^[a-z0-9_]+$`; default `raspberry`; host var `keepass_database` (dungeon: `dungeon`),
  `keepass_ca_database: raspberry`. Master password env: `KEEPASS_PASSWORD` (raspberry),
  `KEEPASS_PASSWORD_<NAME upper>` (others). Windows credential `<name>-keepass`, user `keepass`.
- KeePass entries: `Backup/Resticprofile` (`passphrase`), `Discord/Docker Webhook` (`id`, `token`; testbed:
  `Discord/Docker Webhook testbed`), `smart-home/outbound`, `Backup/Resticprofile SSH` with attachments `id_ed25519`
  and `id_ed25519.pub` (testbed: `Backup/Resticprofile SSH testbed`).
- dungeon: `base_dns_servers: [192.168.1.2]`, `docker_daemon_dns: [192.168.1.2]`, rsnapshot off, `argon_fan` off,
  `dhparameter_bits: 4096`, no smart-home `.env`, `resticprofile_backup_stacks: [infrastructure]`,
  vhosts and certificate SANs `[portainer, outbound]`.
- Conventions: TDD, `.yaml`, FQCN, `no_log: true` on every task with secret values, `ansible-lint --strict` 0
  findings, idempotent, English in the repo, commits `feat:/fix:/test:/docs:` with `Refs #15`.
- Never run anything against raspi or dungeon; never edit `.claude/hooks/guard.py` or `.claude/settings*.json`.

## Review Focus

1. Backup SSD missing during the bootstrap: the run stops with "plug in the backup SSD (UUID …)" before it writes
   the marker, `/media/backup/restic` or anything else below the mount point (Task 6 test).
2. Backup SSD missing at backup time: the backup fails in `run-before` instead of writing into the container's
   `/backup` directory (Task 5 template test).
3. Backup SSD missing at restore time: the clean-slate restore stops on the missing marker instead of reading an
   empty repository as "new host" (Task 5 test).
4. A KeePass database name that isn't a valid env var suffix (`my-db`) fails with a clear message, not a silent
   empty password (Task 1 test).
5. `bin/with-keepass` with several stored passwords keeps any `KEEPASS_PASSWORD*` already set in the environment
   (Task 2 test).
